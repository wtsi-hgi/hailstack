- [x] On the live cluster created from commit `4d61198`, `hailstack status --config ~/hailstack/my-cluster.toml --dotenv ~/hailstack/.env --detailed` crashes with `SSHError: master: Unable to parse resource usage for master`. Running the same resource probe through Hailstack's installed SSH helper returns only memory and disk lines (`'4.66976\n13\n'`) because `_run_ssh_command` appends complex remote commands as separate SSH arguments; OpenSSH does not preserve those argument boundaries, so `sh -lc "top ... && free ..."` is split and the CPU pipeline runs incorrectly. Hailstack should quote/join remote command arguments before passing them to `ssh` so detailed status can parse CPU, memory, and disk usage on master and workers.
  - Added a regression proving complex remote commands such as `("sh", "-lc", "<pipeline>")` are passed to OpenSSH as one safely quoted remote command argument.
  - Changed the SSH health helper to use `shlex.join(command)` after the destination host, preserving remote shell argument boundaries while keeping simple service probes intact.
